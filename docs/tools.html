Formatter & linter

One parser serves the compiler, the formatter and the linter, so all three read a template the same way. Both commands split the templates between every core.

Formatter

super_slim fmt [PATH…]           # rewrite templates in place
super_slim fmt --check [PATH…]   # list the ones it would rewrite, exit 1 if any

One layout: two spaces per level, - code and = output spacing, p = output after a tag, no redundant div, no trailing whitespace, single blank lines, one final newline. Text blocks move as a whole, so the whitespace they render stays put.

Before writing a file, the formatter compiles the template before and after, and refuses if the Ruby differs: formatting cannot change a page. A refused file is reported and left untouched, and the command exits 1.

Paths default to the current directory; .git, node_modules, tmp and vendor are skipped.

Linter

$ super-slim lint [PATH…]
app/views/posts/_card.html.slim:3: [ImageAlt] Describe the image with `alt`, or mark it decorative with `alt=""`

29 rules taken from slim-lint, haml-lint, erb_lint, Herb and eslint-plugin-jsx-a11y: layout, template hygiene, Ruby in templates, Rails conventions, HTML and accessibility. It exits 1 when it reports an offense.

Ruby in templates

The Ruby inside templates is RuboCop’s job. SuperSlim ships a RuboCop plugin that hands it each - and = line, code attribute, splat, #{} interpolation and ruby: block, read by SuperSlim’s own parser:

# .rubocop-slim.yml
inherit_from: .rubocop.yml
plugins:
  - super_slim
AllCops:
  Include:
    - "**/*.slim"
$ bundle exec rubocop -c .rubocop-slim.yml app
app/views/posts/show.html.slim:4:20: C: [Correctable] Style/StringLiterals: Prefer single-quoted strings…

Offenses point at their line and column in the .slim file, and --autocorrect writes back into it. The cops that cannot hold in a template, such as indentation across lines or frozen string comments, are off for .slim files. It replaces rubocop-slim, and with it slimi and Temple.

Configuration

Both commands read .super-slim.yml from the current directory. Every key is optional:

tailwind_classes: true     # read templates the way the app compiles them

linters:
  LineLength:
    max: 150                 # default 120
  ConsecutiveControlStatements:
    max: 3                   # lines of `-` before asking for a ruby: block, default 2
  ButtonType:
    enabled: true            # rules off by default: ButtonType, InlineStyles, StrictLocals
  DeprecatedClasses:
    classes:
      text-muted: text-body-secondary
  InstanceVariables:
    enabled: false

In CI

# .github/workflows/lint.yml
- run: bundle exec super-slim fmt --check app
- run: bundle exec super-slim lint app
- run: bundle exec rubocop -c .rubocop-slim.yml app

Both print one line per file or offense, path:line: [Rule] message for the linter, and exit 0 when there is nothing to report, 1 otherwise, 64 on a usage error.
