SuperSlim

Your Slim templates, as they are.A lighter engine, with a formatter and a linter to keep them tidy.

Slim is a Ruby template language that writes HTML with indentation instead of closing tags. SuperSlim is a second engine for it, written from scratch: your .slim files render the same HTML, faster, and come with a formatter and a linter.

gem "super-slim"

A short tour

Seven stops, a minute each. Every one links to the page with the details, if you want them.

  1. 1It reads the Slim you already write

    Nesting replaces closing tags. Lines starting with - run Ruby, = outputs a value escaped for HTML, and the rest are tags, attributes and text. SuperSlim reads Slim 5’s grammar, all but a few parts, and renders what Slim renders with format: :html, sort_attrs: false, down to the byte.

    app/views/posts/index.html.slim

    ul.posts
  - posts.each do |post|
    li
      a href=post.url = post.title
      - if post.draft?
        span.badge Draft

    HTML, with two posts, the second a draft (indented here: SuperSlim writes it on one line)

    <ul class="posts">
  <li>
    <a href="/posts/1">Hello &amp; welcome</a>
  </li>
  <li>
    <a href="/posts/2">Next steps</a>
    <span class="badge">Draft</span>
  </li>
</ul>

  2. 2It does the same work with less

    Compiling a template, which Rails does on the first requests after a deploy and on every reload in development, takes a fraction of the time. Rendering, which happens on every request, is quicker too, and leaves fewer objects behind for Ruby’s garbage collector.

    Loading the latest numbers…

    To be fair about it: in most apps, templates are not what makes a page slow; the database and the network usually weigh more. Expect a snappier reload in development and a lighter load on your servers, not a different app.

  3. 3It tidies templates, without touching the page

    super-slim format gives every template the same layout, so reviews are about what changed, not about spaces. Before writing a file, it compiles the old and the new version and compares the Ruby they produce: if anything but layout differs, it leaves the file alone and tells you.

    Before

    div.card
    -if post.draft?
        span.badge Draft
    =link_to post.title, post


    img src=post.image_url

    After super-slim format

    .card
  - if post.draft?
    span.badge Draft
  = link_to post.title, post

  img src=post.image_url

    The formatter, and its options

  4. 4It points out what is easy to miss

    On the tidy template above, super-slim lint still finds something: an image without a text alternative. Its rules come from tools you may know (slim-lint, haml-lint, erb_lint, RuboCop, Herb, jsx-a11y): layout, Rails conventions, HTML and accessibility. Each has an entry with why it exists, a flagged and a clean example, and its settings.

    $ super-slim lint
_card.html.slim:6: [ImageAlt] Describe the image with `alt`, or mark it decorative with `alt=""`

    For the Ruby inside templates, a RuboCop plugin hands each - and = line to RuboCop, and reports offenses at their line and column in the .slim file.

  5. 5It understands Tailwind, if you ask

    Slim cuts .rounded-b-[3px] at the bracket, renders .size-2.5 as class="size-2 5", and stops at ul.*:p-2 with an error. Turn on one option and the . shortcut takes any Tailwind class name. It is off by default, so switching engines changes nothing until you choose it.

    Template

    .p-1.rounded-b-[3px].lg:hover:underline
.font-['Open_Sans'].mx-0.5.w-1/2
ul.*:p-2

    config/initializers/super_slim.rb

    SuperSlim.tailwind_classes = true

    Tailwind class names

  6. 6It smooths a few rough edges

    Ruby over several lines

    A call can go on after an opening (, [ or { until the bracket closes, the way you would write it in a .rb file.

    Comments after code

    = render card # rubocop:disable … compiles, where Slim turns the line into a syntax error.

    Line numbers you can trust

    Each - and = line compiles onto its template line, so a backtrace points where you look, even after a ruby: block.

    Safer attribute names

    Names only known at render time, like the keys of a data: hash, are checked, so they can’t sneak an onclick into the page.

    Additions to Slim

  7. 7You can try it a little at a time

    Start with the tools alone: with require: false, Rails keeps rendering with Slim, and you get the formatter and the linter. Switch the engine later, or never. Going back is a line in your Gemfile.

    Gemfile, tools only

    gem "super-slim", require: false

    Terminal

    bundle exec super-slim lint
bundle exec super-slim format --check

Is it for you?

A good fit if…

  • your app has Slim templates and runs on Ruby 3.3 or later (Rails 8.0 or later, if Rails);
  • you would like a formatter and a linter that read templates exactly as the engine does;
  • you write Tailwind classes and are tired of moving them into class="".

Maybe not yet if…

  • you rely on the XHTML format, custom shortcuts or Slim’s plugins: see what SuperSlim leaves out;
  • you run JRuby or TruffleRuby: SuperSlim relies on erb/escape, a C extension only CRuby has;
  • you need a project with years behind it: SuperSlim’s first version came out in November 2026. We use it every day on our own production app, and Slim’s own tests keep it honest, but it is young.
